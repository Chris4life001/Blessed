2.1 Create src/middleware/auth.ts:
- verifyToken middleware: reads JWT from Authorization: Bearer header
- If JWT_SECRET is not in env: log warning "JWT_SECRET not configured"
  and return HTTP 503 { error: "Authentication service not available" }
- If token missing: return HTTP 401 { error: "No token provided" }
- If token invalid or expired: return HTTP 401 { error: "Invalid token" }
- If valid: attach decoded user payload to req.user and call next()

2.2 Create src/routes/auth.ts:
- POST /api/auth/register:
  - Validate: email (valid format), password (min 12 chars, 1 uppercase,
    1 number, 1 special char), username (3-30 alphanumeric)
  - Hash password with bcrypt (12 salt rounds)
  - Check for duplicate email — return HTTP 409 if exists
  - Save user to DB
  - Return HTTP 201 { message: "Account created" } — no token on register
- POST /api/auth/login:
  - Validate email and password fields
  - Find user by email — if not found return HTTP 401 (do NOT say "user not found")
  - Compare bcrypt hash — if wrong return HTTP 401 (do NOT say "wrong password")
  - Both cases return identical message: { error: "Invalid credentials" }
  - On success: issue JWT signed with JWT_SECRET, expiry 15 minutes
  - Issue refresh token: signed separately, expiry 7 days, httpOnly cookie
  - Log successful login with user ID and IP (no password in log)
- POST /api/auth/refresh:
  - Read refresh token from httpOnly cookie
  - Verify and issue new access token
  - Rotate refresh token on every use
- POST /api/auth/logout:
  - Clear refresh token cookie
  - Return HTTP 200 { message: "Logged out" }
- GET /api/auth/me:
  - Protected by verifyToken middleware
  - Return authenticated user profile (exclude password hash)

2.3 Password Reset Flow:
- POST /api/auth/forgot-password:
  - Accept email
  - Generate secure random token (crypto.randomBytes(32))
  - Store hashed version in DB with 1 hour expiry
  - Send reset email via SendGrid with reset link
  - Always return HTTP 200 regardless of whether email exists (prevent enumeration)
- POST /api/auth/reset-password:
  - Accept token and new password
  - Validate new password strength
  - Verify token against DB — reject if expired or already used
  - Hash new password and update DB
  - Invalidate token immediately after use
  - Send confirmation email via SendGrid
